MoltRack v0 — Technical Implementation (OpenClaw Runtime)
Overview

MoltRack v0 is a managed runtime for OpenClaw agents.
Each user can create and run persistent OpenClaw agents with a chat interface and usage-based billing.

The system is designed to:

respect OpenClaw’s single-user assumptions

provide strong isolation between agents

centralize authentication, billing, and model access

avoid modifying OpenClaw core in v0

Core Design Principles

One agent = one OpenClaw gateway

Isolation via containers, not in-process multi-tenancy

Backend owns auth, billing, and model routing

OpenClaw remains headless and unexposed

Persistence via mounted volumes

PAYG enforced before model execution

Identity & Authentication
User Identity

Managed via Privy

Primary identifier: privy_user_id

X handle is metadata, not a primary key

Runtime Identity

Each agent runtime has:

agent_runtime_id (UUID)

agent_runtime_token (random secret)

These credentials are:

generated by backend

injected into the container

used for OpenClaw ↔ backend authentication

User sessions are never exposed to containers.

Starting an Agent (Canonical Flow)
1. Validation

Backend verifies:

user owns agent

agent is currently stopped

user account is active

optional: minimum credit balance

2. Runtime Credential Generation

Backend generates:

agent_runtime_id

agent_runtime_token

Only hashes are stored in the database.

3. Persistent Storage Provisioning

Each agent gets a dedicated directory on the host:

/var/moltrack/agents/<agent_id>/
└── .openclaw/
    ├── agents/
    ├── sessions/
    └── config/


This directory is mounted into the container as:

/root/.openclaw


This is required for:

agent memory

session persistence

crash recovery

4. Container Launch

The backend launches an OpenClaw container:

docker run -d \
  --name openclaw-agent-<agent_id> \
  -p 127.0.0.1:<random_port>:18789 \
  -v /var/moltrack/agents/<agent_id>:/root/.openclaw \
  -e OPENCLAW_GATEWAY_PORT=18789 \
  -e OPENCLAW_API_BASE=https://api.yourdomain.com/llm \
  -e OPENCLAW_API_KEY=<agent_runtime_token> \
  -e AGENT_RUNTIME_ID=<agent_runtime_id> \
  -e TZ=UTC \
  openclaw:latest


Key properties:

OpenClaw is not publicly exposed

One container per agent

Filesystem fully isolated

Model access is redirected to backend

5. OpenClaw Gateway Startup

Inside the container:

openclaw gateway is started

Gateway loads state from /root/.openclaw

HTTP API is exposed on port 18789

At this point:

Gateway exists

No agent exists yet

6. Agent Creation (Explicit)

Backend creates the agent inside OpenClaw:

POST http://127.0.0.1:<port>/v1/agents
Authorization: Bearer <agent_runtime_token>


Payload:

{
  "name": "Agent Name",
  "system_prompt": "...",
  "tools": []
}


The returned openclaw_agent_id is stored and mapped to the MoltRack agent record.

Agent state transitions to running.

7. Health Check

Backend verifies:

agent exists

gateway responds

optional: test session creation

If any step fails:

container is stopped

agent marked as errored

error surfaced to user

Chat Execution Flow
1. User Sends Message
POST /agents/:agentId/chat


Backend verifies:

ownership

agent is running

sufficient credits

2. Session Management (OpenClaw)

Backend:

creates or reuses an OpenClaw session

forwards user message to session

3. Model Call (Proxy)

When OpenClaw needs an LLM:

it sends a request to OPENCLAW_API_BASE

includes OPENCLAW_API_KEY

Backend LLM proxy:

authenticates runtime token

resolves user + agent

pre-authorizes credit spend

calls OpenRouter

receives response + usage

deducts credits

returns response

4. Response Delivery

OpenClaw appends response to session

backend streams response to frontend

UI updates in real time

Billing Model

PAYG via internal credits

Credits purchased via Stripe

Each LLM request is:

pre-authorized

reconciled post-usage

Hard stop when balance reaches zero

No negative balances.
No deferred billing.

Stopping an Agent
POST /agents/:agentId/stop


Backend:

stops container

preserves volume

marks agent as stopped

No memory is lost.
No compute cost continues.

Failure & Recovery
Container Crash

volume persists

agent can be restarted

memory rehydrates automatically

User Disconnects

agent continues running

idle timeout can auto-stop

Backend Restart

containers continue running

agent state reloaded from DB

Security Model

One agent per container

No shared filesystem

No shared network exposure

No provider API keys in containers

All LLM access proxied

Minimal tool surface in v0

Blast radius is limited to a single agent.

What Is Explicitly Out of Scope (v0)

Browser tools

Shell access

Multi-agent coordination

Plugins marketplace

Tokenization / contracts

Autonomous trading

These are layered after runtime stability.

Summary

MoltRack v0 provides:

isolated OpenClaw runtimes

persistent agent memory

centralized model access

usage-based billing

safe, predictable execution

It does this by wrapping OpenClaw, not modifying it, and by enforcing isolation at the container boundary.

This foundation is intentionally boring — because everything powerful comes later.
